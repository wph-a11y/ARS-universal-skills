# 假设驱动的实验循环协议（Experiment Loop Protocol）

## 迭代单元

一个完整迭代单元 = 一个假设的一次"设计→执行→裁决"。循环终止条件只有三种（见 decision_gates.md 结果即停）：目标达成、假设证伪、预算耗尽（预算耗尽属 ESCALATE 后的受控停止）。

## 假设账本格式

`experiments/hypothesis_ledger.md`：

```markdown
| ID | 假设 | 预期观察 | 证伪条件 | 来源 | 状态 | 裁决依据 |
|----|------|---------|---------|------|------|---------|
| H1 | 将窗口从48增至96, FD001 RMSE 下降≥3% | ... | RMSE 持平或上升 | 文献[X]2025 | testing | exp_003 |
```

规则：
- 状态机：`pending → testing → supported / falsified / inconclusive`
- 不允许删除或改写已裁决假设；修正只能新增 H<n+1> 并注明由谁衍生
- 每个 supported 假设必须挂实验日志路径；无日志的 supported 无效

## 优先级排序

多假设并行时按"信息增益 / 预算"排序：
1. 能证伪核心前提的假设优先（证伪价值高）
2. 单次成本低、周期短的优先（快速失败）
3. 与已 supported 假设耦合的衍生假设在主线确认后再跑

## 防止系统性自欺

- **先定指标后跑实验**：设计文档未写明主指标的实验不准启动
- **基线先行**：任何新方法的比较前，必须先在本地复现基线数值（或引用文献数值并声明环境差异）
- **禁止指标购物**：跑完后更换主指标以"找到"改善 = 违反协议；额外指标只能作次指标分析
- **泄漏自查**：每次用测试集出数前，确认测试集未参与任何训练/调参决策

## 与论文写作的衔接

假设账本即论文的论证骨架：Introduction 的贡献点、Method 的动机、Experiments 的表格均应能映射到账本条目。映射不上的实验内容要么补假设，要么从论文中删除。
